# Jev Browser 0.14.0

This release adds two opt-in screen features, opt-in image understanding for
text-only callers and following new tabs in screen-only sessions, makes `run()`
re-verify its evidence and targets after waits, and sends smaller action
decision requests. It has no breaking changes; the behavior notes below list
the few results that can differ from 0.13.0.

## Upgrading from 0.13.0

No code or configuration change is required. Check these if you depend on the
exact results:

- **Extraction evidence keys.** `extract()` evidence keys escape a literal `.`
  or `\` inside a field name with `\`: a field named `a.b` is now keyed
  `a\.b`, while a nested `{a: {b: …}}` stays `a.b`. A field under an empty
  name no longer shares a key with a root field. In 0.13.0 such names could
  collide with other keys; ordinary field names, array indexes and the scalar
  root `value` key are unchanged.
- **Decision request budget.** An `act` or `observe` decision request larger
  than 128 KiB now fails with `OBSERVATION_LIMIT` before any provider call.
  Hosted Jev already rejected such requests, which reached callers as
  `PROVIDER_ERROR`. Option decisions and batched decision questions already
  used this budget. Narrow `scope`, or lower `maxElements`, `maxTexts` or
  `maxCandidates`, as the error says.
- **Stale targets.** Plans, snapshot refs, `run` actions and owned combobox
  options are re-checked right before the effect. A target that left the Page,
  document, frame or observation scope it was captured in now fails with
  `STALE_TARGET` instead of being clicked.
- **Dialogs during a capture.** A native dialog that opens while `screen`
  captures is always reported once as `SCREEN_FAILED` (or
  `SCREEN_INTERRUPTED` after an input) with reason `dialog`. In screen-only
  sessions it could previously surface as `SCREEN_DIALOG_UNSUPPORTED` instead,
  depending on timing.

## Opt-in image understanding

`screenDecide` (CLI `screen_decide`, MCP `browser_screen_decide`) captures the
viewport once, has an OpenAI-compatible Chat Completions endpoint you configure
describe it, and answers your questions with Jev from that description. It
sends no input; `evidence.observationId` is the current screen observation, so
you can act on it with `screen`.

- SDK: `JevBrowser.launch({ vision: { baseURL, model, apiKey?, timeoutMs? } })`,
  or your own `ImageUnderstanding` adapter. `decideFromScreen` and
  `ChatCompletionsImageUnderstanding` are exported for captures you already
  have.
- CLI/MCP: `--vision-base-url` and `--vision-model` together, with the key only
  from `JEV_VISION_API_KEY`. They are fixed when a session opens, and the MCP
  tool is listed only when they are set. It also works in `--screen-only`
  sessions. Without configuration it fails with `CONFIG`.
- The image endpoint must be HTTPS or loopback, receives only the frames,
  capture times and pixel size, and never receives a Jev key. The decision
  endpoint receives text only.

Normal operations and `screen` never call the image endpoint. See
`docs/image-understanding.md`.

## Following new tabs in screen-only sessions

The new `screenFollowPopups` launch option (CLI/MCP `--screen-follow-popups`,
together with screen-only mode) makes a new tab opened by the observed page the
observed page instead of closing it. The result that first observes it reports
`pageSwitched: 'popup'`; an input meant for the previous page fails with
`STALE_SCREEN` and sends nothing. When the followed tab closes, observation
returns to its opener with `pageSwitched: 'opener'`. Without the option, a new
tab is still reported once with `SCREEN_POPUP_UNSUPPORTED` and closed. See
`docs/screen-review.md`.

## `run()` evidence and waits

- A UI readback becomes a checkpoint only after re-reading that the same
  result record and page headings, status and alerts are still shown;
  otherwise `run()` observes again. The save is never repeated.
- Progress waits watch only the observed frames and scope roots, so a change in
  an unrelated frame or outside `scope` no longer ends a wait early.
- `run()` re-decides instead of executing a speculative action on a control
  whose input it just applied, and a "done" answer given before inputs were
  applied no longer skips to the final `expect`.
- If the Page closes while a `run()` pauses, its own result or error is
  returned and no continuation is kept.

## Smaller decision requests

`act`, `observe` and `run` no longer send link URLs in their decision state,
and decision requests omit `frame` for the main frame. On a 40-row table with a
link per row, the observe request shrank from about 99.5 KB to 86.2 KB.
`extract` and semantic evidence keep link URLs, and link `href` sources have
their own budget instead of counting toward `maxTexts`.

## Documentation

`console_messages` and `network_requests` are documented as Page-scoped: cores
sharing one Page each record all of that Page's events in their own buffer, and
`clear: true` empties only that core's buffer. Give a core its own Page to
attribute events to it.

## Installation

```sh
npm install --save-dev https://github.com/tontoko/jev-browser/releases/download/v0.14.0/tontoko-jev-browser-0.14.0.tgz
npx jev-browser install chromium
```

npm 7+ and pnpm install the `playwright-core` and `zod` peers automatically;
with Yarn Berry, add them explicitly:
`yarn add -D ./tontoko-jev-browser-0.14.0.tgz playwright-core zod`.

This is GitHub Release tarball distribution, not an npm registry publication.
Verification and recovery follow the 0.10.0 notes: publication happens from CI
only after every platform job succeeds and never overwrites an existing tag.
