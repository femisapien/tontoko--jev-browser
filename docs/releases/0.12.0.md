# Jev Browser 0.12.0

This release changes where hosted API keys are sent, how borrowed Pages treat
dialogs and tab events, and which error codes operations report. Read the
breaking changes before updating a dependency pin. `docs/migration.md` has the
full migration notes under the sections marked "next release".

## Breaking change: hosted keys stay with hosted Jev

`JEV_API_KEY` and `TYPESAFE_API_KEY` are now sent only to hosted Jev at
`https://api.typesafe.ai`. Earlier releases also sent them to a custom
`baseURL` / `JEV_BASE_URL`, so a mistyped or untrusted endpoint received the
hosted key. A custom endpoint now gets a fixed placeholder key unless it is
authenticated explicitly.

Migration:

- SDK: pass `apiKey` together with `baseURL`.
- CLI and MCP: set `JEV_ENDPOINT_API_KEY`. A proxy that forwards the hosted key
  needs it the same way, for example `JEV_ENDPOINT_API_KEY="$JEV_API_KEY"`.
- A key is sent only over HTTPS or to a loopback host. A key for an `http://`
  endpoint on another host fails with `CONFIG`. Keyless custom endpoints,
  including plain HTTP ones, work as before.
- The upstream SDK's `TYPESAFE_BASE_URL` no longer redirects this library; use
  `JEV_BASE_URL`.

Empty or whitespace-only key variables, such as `JEV_API_KEY=` from
`.env.example`, now count as unset. An explicit `apiKey` no longer appears when
a `JevBrowser` is inspected, logged or serialized.

## Behaviour change: borrowed Pages, dialogs and tab-scoped events

A `JevBrowser` constructed with a borrowed Page no longer holds dialogs between
its operations. Playwright's default dismissal applies to the caller's own Page
actions, so a `page.click()` that opens `confirm()` no longer hangs and later
Jev operations no longer fail with `DIALOG_PENDING`. Dialogs that open during a
Jev operation are still held and returned as a pending `dialog`. Pass
`captureDialogs: true` to keep the previous behaviour. `JevBrowser.launch()`,
the CLI and the MCP server keep holding dialogs by default.

`console_messages`, `network_requests` and `downloads` `list` now report the
selected tab. Add `allTabs: true` where a multi-tab caller read every tab.
Entries carry a `pageId` matching `tabs` results. Save or cancel downloads by
the new stable `id`; an `index` now addresses the selected tab's list.
`file_upload` without a target uses only a chooser opened on the selected tab,
and fails with `NO_FILE_CHOOSER` after that tab navigates. Single-tab sessions
see the same entries as before, with the added fields.

## Breaking change: timeouts and error codes

- An exhausted `timeoutMs` budget fails with `TIMEOUT` instead of `CANCELLED`.
  `CANCELLED` remains for an aborted caller `signal` and for `close()` during
  an operation. Code that treated `CANCELLED` as "timed out or cancelled"
  should accept both.
- `JevBrowser` operations reject with `BrowserError` instead of raw Playwright
  errors. Read `error.code`; the original error is `error.cause` and is never
  serialized.
- New codes: `TARGET_OBSCURED` (previously `ACTION_INTERRUPTED` for a click
  that was never delivered), `AMBIGUOUS_TARGET`, `INVALID_SELECTOR`,
  `NAVIGATION_FAILED` and `BROWSER_LAUNCH_FAILED`. Native `assert` reports
  target read errors such as `AMBIGUOUS_TARGET` instead of `ASSERTION_FAILED`.
- `BrowserError` and CLI/MCP error JSON add a `retryable` flag. It never
  authorizes repeating an action whose effect is unknown.
- An explicit `scope` that matches no element fails with `SCOPE_NOT_FOUND` in
  `snapshot`, `observe`, `act`, `extract` and the semantic locate, compare and
  assert methods instead of returning an empty observation. `run` and `resume`
  are unchanged.

Operations now end at their budget even when page work ignores cancellation,
and `close()` closes owned browsers after about one second instead of waiting
indefinitely. It never closes a borrowed Page, context or browser.

## Observation and screen mode

- Text longer than 700 characters is observed as its first 700 characters with
  `truncated: true` and counts toward `maxTexts`, so long pages can reach
  `OBSERVATION_LIMIT` sooner.
- A capture interrupted by navigation is retaken after the new document loads;
  a page that keeps navigating fails with `STALE_SNAPSHOT`.
- Screen mode: only main-frame navigations invalidate an observation, rejected
  requests keep the latest observation usable, capture waits for a started
  navigation and retakes once, and `SCREEN_FAILED` / `SCREEN_INTERRUPTED` add a
  `details.reason`. A native file chooser is reported once and the page stays
  usable. The screen journal starts with a `header` row and frames add
  `sha256`, `width` and `height`.
- A wizard run that stops before its first verified save can return a
  `continuation` for `resume()`.

## CLI and MCP

- New `--viewport WxH`, `--reduced-motion`, `--color-scheme`, `--locale` and
  `--options-file FILE` for launch and context options.
- The MCP server queues parallel tool calls in arrival order instead of
  returning `BUSY`, and replaces a browser whose launch failed or that crashed
  or disconnected on the next call. Screen-only sessions still end.
- MCP tool input schemas describe their arguments (about 13 KB more in
  `tools/list`).
- Integer command arguments accept at most 2147483647; larger timeouts
  previously overflowed Node timers.

## Fixes

- Persistent sessions no longer corrupt multibyte UTF-8 text in large command
  bodies.
- The SDK no longer loads Playwright Test at runtime, so a project with a
  different `@playwright/test` version can pass its test `page`.
- Numeric input values echoed by the page are redacted from goal requests and
  results.
- `dom-accessibility-api` moved to development dependencies because it ships
  only inside the DOM bundle; the unused `dist/dom.js` is no longer packed.

## Installation

```sh
npm install --save-dev https://github.com/tontoko/jev-browser/releases/download/v0.12.0/tontoko-jev-browser-0.12.0.tgz
npx jev-browser install chromium
```

This is GitHub Release tarball distribution, not an npm registry publication.
Verification and recovery follow the 0.10.0 notes: publication happens from CI
only after every platform job succeeds and never overwrites an existing tag.
