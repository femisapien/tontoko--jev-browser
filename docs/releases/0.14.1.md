# Jev Browser 0.14.1

This patch release reports decision requests that hosted Jev rejects as too
large as `OBSERVATION_LIMIT` with narrowing guidance, instead of a generic
`PROVIDER_ERROR`. It has no breaking changes.

## Upgrading from 0.14.0

No code or configuration change is required. If you handle errors by code:

- **Token limit rejections.** Hosted Jev limits decision requests by input
  tokens, not bytes. Dense pages, such as tables of short cells with a link per
  row, reach that limit well below the 128 KiB byte budget. The service rejected
  them with HTTP 400 `max_tokens_exceeded`, which reached callers as a
  non-retryable `PROVIDER_ERROR` ("Jev request failed (HTTP 400)"). That
  rejection now fails with `OBSERVATION_LIMIT` (`retryable: false`) from
  `act`, `observe`, `run`, `extract` and the semantic operations. As the message
  says, narrow `scope`, use `exclude`, or lower `maxElements`, `maxTexts` or
  `maxCandidates`. Other provider failures are still `PROVIDER_ERROR`, with
  unchanged retryability.

## Decision request budget

The 128 KiB byte budget checked before a provider call is unchanged. A live
measurement found the hosted limit at roughly 32-33k input tokens. The ratio of
bytes to tokens depends on the request shape: a 35-row table request of about
77 KB was rejected, while a prose-heavy request of about 116 KB was accepted. A
lower byte budget would therefore reject requests the service accepts. The
service can still reject smaller requests, and that rejection now surfaces as
`OBSERVATION_LIMIT`. See `docs/api.md`.

## Installation

```sh
npm install --save-dev https://github.com/tontoko/jev-browser/releases/download/v0.14.1/tontoko-jev-browser-0.14.1.tgz
npx jev-browser install chromium
```

npm 7+ and pnpm install the `playwright-core` and `zod` peers automatically;
with Yarn Berry, add them explicitly:
`yarn add -D ./tontoko-jev-browser-0.14.1.tgz playwright-core zod`.

This is GitHub Release tarball distribution, not an npm registry publication.
Verification and recovery follow the 0.10.0 notes: publication happens from CI
only after every platform job succeeds and never overwrites an existing tag.
