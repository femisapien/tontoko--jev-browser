# Jev Browser 0.14.2

This patch release fixes two timing-dependent `run()` results. It has no
breaking changes.

## Upgrading from 0.14.1

No code or configuration change is required.

- **Combobox options shown at the deadline.** `run()` combobox selection waits
  up to `settleTimeoutMs` for a matching option. With a short budget on a slow
  machine, the wait could expire between two polls and fail with `NO_MATCH`
  even though the option was already on screen. The wait now polls in
  proportion to the budget and checks the page once more at the deadline.
  `NO_MATCH` now means that no matching option was shown when the budget
  expired. A combobox whose shown popup lies outside the observed scope now
  consistently fails with `STALE_TARGET`, instead of sometimes `NO_MATCH`.
- **Form replaced before an onward click.** When a page replaced the form that
  `run()` had just filled and authorized, before an onward click such as
  "Next" or "Search", `run()` could stop with reason `validation` because the
  filled input was no longer attached. It now observes the page again and
  decides on the new form. The click itself is not retried automatically.

## Installation

```sh
npm install --save-dev https://github.com/tontoko/jev-browser/releases/download/v0.14.2/tontoko-jev-browser-0.14.2.tgz
npx jev-browser install chromium
```

npm 7+ and pnpm install the `playwright-core` and `zod` peers automatically;
with Yarn Berry, add them explicitly:
`yarn add -D ./tontoko-jev-browser-0.14.2.tgz playwright-core zod`.

This is GitHub Release tarball distribution, not an npm registry publication.
Verification and recovery follow the 0.10.0 notes: publication happens from CI
only after every platform job succeeds and never overwrites an existing tag.
